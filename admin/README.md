# ReelCraft Studio — Admin Panel

A dark, cinematic admin dashboard for a video-production studio: leads, projects, shoot calendar, clients, portfolio, services, team, testimonials, content planning, invoices, payments, expenses and reports — backed by Supabase with Row Level Security.

**Stack:** React 19 · TypeScript · Vite 8 · Tailwind CSS 4 · Recharts · React Hook Form + Zod · React Router 7 · date-fns · Lucide · Supabase (Postgres, Auth, Storage).

> UI components are hand-written in the shadcn/ui style (`src/components/ui/`) rather than generated by the shadcn CLI, so there is no `components.json` and no Radix dependency.

---

## Quick start (demo mode — no backend needed)

```bash
npm install
npm run dev          # http://localhost:5173
```

With no Supabase variables set the app runs in **demo mode**: realistic, clearly-labelled sample data stored only in your browser (localStorage), a banner on every page, and a role picker instead of a login so you can see what Owner, Manager, Editor, Videographer and Accounts each get. The demo store reproduces the database's rules (auto codes, invoice totals, overpayment guard, booking clashes, cascades, role access), so every button works. Reset or empty it from **Settings → Data & website**.

## Going live with Supabase

1. **Create a Supabase project** (region close to India, e.g. Mumbai `ap-south-1`).
2. **Run the migrations** in order — either `supabase db push` with the Supabase CLI, or paste each file into the SQL editor:
   ```
   supabase/migrations/20261026000001_schema.sql            tables, enums, indexes, constraints
   supabase/migrations/20261026000002_functions.sql         triggers & RPCs (invoice maths, conflicts, conversion, activity log)
   supabase/migrations/20261026000003_rls.sql               Row Level Security for every table, function grants
   supabase/migrations/20261026000004_storage_public_api.sql storage buckets + policies, public website API
   ```
3. **Auth settings** (Dashboard → Authentication):
   - *URL configuration*: set Site URL to your admin domain and add `https://your-admin-domain/update-password` to redirect URLs (password reset).
   - *Providers → Email*: after the owner has signed up, **disable sign-ups** and invite staff from *Users → Invite* instead.
   - Turn on leaked-password protection; consider MFA.
4. **Environment**: copy `.env.example` to `.env.local` and set `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` (Project Settings → API). Only the publishable/anon key belongs here — **never the service-role key**.
5. **First login**: the first account that signs up becomes the active **Owner**. Every later sign-up is created *inactive with no role* and sees a "waiting for approval" screen until an owner assigns a role in **Settings → Users & roles**.
6. Add your team in **Team**, link each person to their login (so "assigned to me" and project-level edit rights work), then add services, portfolio items and so on.

Demo data is never written to Supabase. A live project starts empty except for one `studio_settings` row.

## Roles & security

| | Owner | Manager | Accounts | Editor | Videographer |
|---|---|---|---|---|---|
| Enquiries | full | full | view | — | — |
| Projects | full | full | view | edit **assigned** | edit **assigned** |
| Project budgets / dues | ✓ | ✓ | ✓ | hidden | hidden |
| Bookings | full | full | view | view | view |
| Clients | full | create/edit | create/edit | view | view |
| Portfolio · Testimonials · Content | full | full | — | full | view |
| Services · Team | full | full | view | view | view |
| Invoices · Payments · Expenses | full | view | full | — | — |
| Settings · Users | full | view | view | view | view |

- Enforced in Postgres with RLS (`supabase/migrations/…_rls.sql`); the UI (`src/lib/permissions.ts`) mirrors it to hide what a role can't use.
- Budgets live in a separate `project_financials` table so editors/videographers can work on projects without seeing money.
- Only owners can change roles or activation (trigger `guard_profile_changes`), and an owner can't lock themselves out.
- Invoice totals, balances and statuses are computed by triggers from line items and payments; the client never supplies them. Payments that exceed an invoice balance are rejected. Projects with recorded payments can't be deleted.
- Overlapping active bookings sharing a crew member or a named equipment item are rejected by triggers (`booking_conflicts`); the form warns before you save.
- Anonymous visitors have **no table access** except reading active services, published portfolio items and approved testimonials. Website forms go through `submit_enquiry` / `submit_booking_request`, which validate input, drop honeypot-filled bot submissions, rate-limit per IP (5/hour/kind, 30/minute overall) and de-duplicate repeats within 24 h.
- Storage buckets: `portfolio` (public read, 50 MB, images/video), `branding` (public, 5 MB), `avatars` (public, 2 MB), `receipts` (**private**, 10 MB, signed URLs, finance roles only).

## Website integration

The existing website keeps its own framework. Two options:

**A. Drop-in script** (any site, no build): served by this app at `/embed/reelcraft-forms.js`.
```html
<script src="https://YOUR-ADMIN-DOMAIN/embed/reelcraft-forms.js"
        data-supabase-url="https://YOUR-PROJECT.supabase.co"
        data-supabase-key="YOUR_PUBLISHABLE_KEY" defer></script>
<div data-reelcraft-form="enquiry"></div>   <!-- contact / quote form -->
<div data-reelcraft-form="booking"></div>   <!-- "Book a Shoot" form -->
```
Includes loading, success, duplicate and error states and blocks double-clicks.

**B. Your own code** — see `src/features/website/PublicSitePage.tsx` (live preview at `/site`) for a React reference: services, portfolio with YouTube/Vimeo embeds, testimonials, both forms and a WhatsApp button. Read public content with:
```
GET /rest/v1/services?select=*&is_active=eq.true&order=sort_order
GET /rest/v1/portfolio_items?select=*&is_published=eq.true&order=is_featured.desc,sort_order
GET /rest/v1/testimonials?select=*&status=eq.approved&order=sort_order
```
Submissions appear immediately in **Enquiries** (marked "website") and **Bookings** (as *Requested*, awaiting staff confirmation), with a bell notification. Portfolio/service changes appear on the site as soon as they're published.

## Deploy (Vercel)

1. Push to GitHub and import the repo in Vercel (framework: Vite — `vercel.json` is included with SPA rewrites and security headers).
2. Add `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` as environment variables, deploy.
3. Add the deployed URL to Supabase Auth → URL configuration.

Netlify/Cloudflare Pages also work (`public/_redirects` handles SPA routing): build `npm run build`, publish `dist`.

## Conventions

- **Currency** INR, Indian digit grouping (₹2,45,000; compact ₹2.45L). **Time zone** Asia/Kolkata everywhere: datetime inputs are IST wall-clock and stored as UTC instants (IST has no DST, so conversion is exact). "This financial year" runs April–March.
- Invoice numbers: `RC-26-0001` (prefix + 2-digit year + sequence), configurable in Settings.
- "Collected" = payments received; "Invoiced" = issued invoices excluding drafts/voids; "Estimated profit" = collected − recorded expenses.

## What's done, and what isn't

**Implemented and tested:** every module in the brief with working create/edit/delete, search, filters, sorting, pagination, CSV export, loading/empty/error states, confirmations; enquiry → client + project conversion; project table + Kanban (drag-and-drop or "Move to"), workflow stepper, deliverables, revisions, approval, team assignment, advances; month/week/day booking calendar with crew/equipment clash prevention; client detail with projects, invoices, bookings and communication history; invoice editor with tax/discount and live totals, printable invoice (Print → Save as PDF), partial/full payments; expenses with receipt upload; reports with date filters; settings, user approval and roles; password reset; idle sign-out; responsive layout and mobile drawer.

**Not included / needs configuration:**
- **Live Supabase run** — migrations are verified against Postgres 17 (PGlite) with stubbed `auth`/`storage` schemas, not yet against a hosted project. Run `npm run test:db` and apply to a staging project first.
- **PDF** export uses the browser's print dialog (A4 print stylesheet), not a server-generated PDF.
- **Email/WhatsApp notifications** — notifications are in-app only; sending email or WhatsApp needs an external provider (e.g. a Supabase Edge Function + Resend / WhatsApp Business API).
- **Social publishing** — the content calendar is planning-only; nothing is auto-posted.
- **Staff invitations** — use Supabase Dashboard → Users → Invite (an in-app invite needs a server-side function holding the service-role key).
- **Overdue status** refreshes whenever an invoice changes; to flip untouched invoices to *Overdue* daily, schedule `select public.refresh_overdue_invoices();` with pg_cron.
- Shoots are single-day (start and end on the same date); the original website screenshot wasn't attached, so branding follows the dashboard reference.
- Lists load each table fully (paged in 1,000-row chunks) and filter in the browser — comfortable for a studio's volume (tens of thousands of rows); add server-side pagination if it grows beyond that.
